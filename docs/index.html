Altheastix eBay Order Manager, a Tampermonkey userscript

eBay picking, packing, and shipping at scale

eBay tells me what sold, not which warehouse box the sticker is in, what envelope it needs, or what I've already packed and marked as shipped. An 8,900-line Tampermonkey userscript fixes that, and cut my daily order processing from 45 minutes to about 12.

the job

10-15 orders a day. Every one of them is a physical object in a numbered box.

Altheastix ships about 350 items a month, mostly stickers. Each order is a trip to a box, a count, a ziplock, an envelope, a postage decision and a walk to the mailbox.

So the SKU matters: B04 is a drawer and a position in it. The panel is a picking list, not an order list. Eight steps:

No single feature does it. A batch of fifteen stops needing fifteen rounds of attention, and no longer needs re-checking to find out what went out.

Why eBay's own page doesn't work for thisshow

eBay's page buys postage. I needed one that runs a pick-and-pack.

Each order gets weight, dimension, service and insurance fields, all irrelevant for a one-ounce $5 sticker. The two fields that decide what to fetch, SKU and quantity, are 12px grey under the title. But almost everything a pick-and-pack tool needs is on the page.

What packing needsWhat eBay's page gives
Which box the sticker is in SKU, 12px grey, under the title
How many to count out “Qty: 3”, same grey, same size
One list of everything to pick A pick list, per order
Printable addresses for a home printer None. Labels are bought, not printed
Which orders need a manila envelope None. Open each one and read it
Orders that arrived since the page loaded None. The page is a snapshot
What's already packed None
Weight and dimensions Six inputs per order
Insurance Two radios per order

The pick list was the one part shaped like the job. The rest is a rebuild around the eight steps.

what was built

The rebuilt page, part by part.

Same URL, same orders, same eBay session. The script replaces the layout in the browser. Click a marker.

1

1 · picking

The SKU is a shelf address.

Stickers are stored in lettered boxes. F24 is the 24th sticker in box F. Sorted alphabetically, the SKU list becomes a walking route: open box A once, take everything from it, move on.

F24
box Fcontainer on the shelf
sticker 24position in that box

Suffixes carry the packing rule:

  • E59B Bitcoin ×3 three of one SKU
  • B01D 5in Lg oversized, different envelope
  • M02 set, manila envelope
  • F01 🇨🇦 Canada, international stamp
  • A07* over $25, goes out as an eBay label with tracking

One pill per order line, sorted by SKU and grouped by letter, so each box is opened once. ×3 means count out three. Click a pill to jump to its order; the filter matches SKU, buyer and title. Packed orders strike through instead of vanishing, so the list holds still. Inside a card, items follow box order too, and a SKU eBay left blank is filled in from the listing.

Colour is physical. A multi-SKU order gets its own colour on every one of its pills, so what goes in one envelope reads as a group across boxes. A green wash or amber ×2 means more than one of a SKU, the most common packing mistake. Thick yellow border: large sticker. Orange: manila. A yellow *: over $25, tracked label.

2 · new orders, no reload

The page is a snapshot. It checks for new sales in the background.

A sale twenty minutes into packing is invisible until you reload, and reloading mid-batch loses selections and edits. So every 5 minutes the script asks eBay for the current order ids and compares them with the ones it loaded.

v3.26–4.36 three kinds of postage

v3.34–4.68 the address as data to be linted

A stamped envelope is an expensive place to discover a bad address.

Before printing, each address is linted: line count, a real name, a house number (or PO Box), a valid City ST 12345 line and one of 59 US state and territory codes. Canada gets its postal code and 13 provinces checked. Two rules exist for quirks: eBay sometimes puts the street number on its own line, and Wisconsin grid addresses (W140S7748) start with a letter.

Fixing what buyers type

A unit glued to its number (Apt98), a unit on the street line, a unit typed twice: each is one click on Fix, with Undo. Only the card and the envelope change, never eBay.

Does the address actually exist?

Each US address is also checked against USPS's delivery list, through Google's Address Validation API on the Mac Mini. The tooltip says deliverable, needs an apartment number, not deliverable or ZIP should be …, and a warning turns ✔ into ⚠.

  • Fix and Edit re-check, so the badge describes what will print.
  • Use USPS puts USPS's version on the card when it really differs.
  • Cheap and private: street to ZIP only, never the name; cached; at most 150 a day, inside Google's free tier.

The real validateAddress(), ported verbatim. Load a broken sample or press Fix. The USPS check needs the Mini, so it isn't here.

v4.23–4.35 a batch you can walk away from

Forty orders, one at a time, each waiting for a real outcome before the next begins.

Orders run one at a time, each waiting for eBay's answer, after a dialog states the count and the expected time: about 8 seconds an order through the Mini API, about 30 through tabs.

Ready
0 shipped · 8 to go

Run it. One of the eight fails to ship; one ships but fails to message. At the end the rescue sweep retries the un-messaged card once, in the background, and reports the result.

  • One attempt per card, per batch. The marker is written before the tab opens, so a crash or re-render can't loop into mailing the same buyer twice.
  • An unknown draft action is skipped, not defaulted to auto-send.
  • Two failures ends it, and the card keeps its pill for you to finish.
  • Retries open in the background; the manual Retry button opens in the foreground.

Pasted into eBay's composer. The text sent is exactly the preview, hand edits included. The modal closes; the tab that sends it stays open until eBay confirms.

The real modal. The first name comes from the order, de-capitalised (JAMIE → “Jamie”). Typed fields show in green, an empty one shows as a pill, and the preview itself is editable: what you see is what is sent.

The automatic thank-you works the same way: nouns and pronouns match the quantity, the tracking line appears only when tracked, and “tomorrow” skips Sunday.

Sending it was the hard part

Four timing bugs, from clicking before eBay's page was ready to the tab closing before anyone checked. Now each step retries, and the tab closes only on proof the message went out; otherwise it stays open with the draft and a red banner.

Retry can never double-send

The ship note and the thank-you are one-shot, guarded per order, so retrying a failed shipment never mails the buyer twice. The draft is deleted only once its text is in the box, so a retry resends the same words.

Since v4.57 the thank-you goes through the eBay API, and the tab is the fallback, used only when nothing went out. A sent one leaves ✉ Thanked 3:03 PM · API on the card. How the API path works →

v4.21 the failure with no channel

Marking an order shipped opens a background tab. Sometimes that tab dies.

Mark as Shipped & Msg opened a background tab that clicked through eBay and closed itself. It nearly always worked. When it didn't, nothing said so:

a card whose ship tab died sat forever showing a green ✔ over the words “Marked as Shipped” while the favicon counter dropped as if the order had gone out. CHANGELOG.md · v4.21

The tab counter dropped too, so a failure made the batch look more finished. Fixing it took five versions and set the rule for everything after: a feature that acts on its own must say when it fails.

v4.21–4.25 three honest states

A card is pending, confirmed, or failed. Never a fourth thing wearing the face of the second.

Pending is an amber spinner. Confirmed is green and arrives only when eBay says so: the script reads eBay's progress stepper (“Ship by Aug 26” becomes “Shipped Aug 23”) and answers unknown when it can't tell, instead of treating a missing button as success. Failed is a red banner quoting what eBay showed, with the tab left open.

Real styles, copy and transitions. Drive it yourself.

diagnostics

Every risky subsystem ships with a report, a dry run, and a simulator.

Each drives the UI into any state without contacting eBay, so a failure banner can be checked without breaking a real order.

The dry run caught a real bug: cards becoming permanently unshippable because two code paths removed the ship button and nothing put it back.

      no automation tab opens, nothing is marked shipped, no buyer is messaged.
    

  










  

    

      
v4.57–4.62 off the page

      

        When eBay opened its API, the tabs became the fallback.
      

      

        For years eBay refused this shop a developer account, so every action was a browser tab the
        script drove. In November 2026 eBay approved one. Shipping, the thank-you and the order note
        now go through the API, and a normal shipment opens no tabs.
      

      

        The browser never holds an eBay credential. A small service on the shop's
        always-on Mac Mini makes the calls. The script logs in once and keeps only a session token.
        Off the shop's private network, requests fail at the door and the tabs take over.

what this says about how I work

      

        I build for the job on the table, not the screen.
      

      

        Every feature started with a physical step: a walk to a box, a count, an envelope. The page
        was rebuilt around that walk, not around eBay's data model.
      

      

        I made the automation honest before making it faster. Five versions went into one green
        checkmark that lied, and every risky part now ships with a report, a dry run and a simulator.
      

      

        I used whatever removed the most drudgery, from StackOverflow to ChatGPT, Gemini, Grok and
        now Claude Code, and kept the design, scope and order of work my own. 177 versions for one
        user, me, each the smallest useful change: that is how a print button became an 8,900-line
        pick-and-pack system.

Two companion scripts

      

        Both cover jobs that happen outside the bulk shipping page, and both install on their own.
      

      

        

          
Offer Msg Picker eBay active listings

          
Ten marketing message templates in the Send Offer modal, with the discount read from the offer form itself rather than hard-coded, so a message can never promise a discount the offer doesn't send. Mounts as a sibling of eBay's React container, because mounting inside it meant the character counter re-created the textarea on every keystroke and stole focus.

        

        

          
Print Address from Gmail mail.google.com

          
A 🖨 Print address button on Etsy and eBay order emails that prints a #10 envelope from the Gmail tab itself. Parses the address out of the rendered message, because Gmail's sanitiser strips <address> entirely. No innerHTML anywhere. Gmail enforces Trusted Types, which made an earlier version throw a CSP violation and do nothing at all.
