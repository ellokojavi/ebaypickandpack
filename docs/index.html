the job

Ten to fifteen orders a day, and every one of them is a physical object in a numbered box.

Altheastix ships around 350 items a month — mostly stickers. An order isn't a database row; it's a trip to a container, a count, a ziplock, an envelope, a decision about postage, and a walk to the mailbox. The eBay page is only the part where you find out what to go and get.

Which is why the SKU on the card matters so much: B04 is not an identifier, it's a drawer. The panel isn't a list of orders. It's a picking list.

The saving isn't any single feature. It's that a batch of fifteen stops requiring fifteen separate rounds of attention — and, more quietly, that the batch no longer needs re-checking afterwards to find out what actually went out.

v4.21 the failure with no channel

Marking an order shipped opens a background tab. Sometimes that tab dies.

Altheastix is a one-person sticker shop. Packing a batch means moving between eBay's bulk shipping page, a stack of #10 envelopes, and a printer — forty times in an evening. This userscript rebuilds that page into something you can actually work at speed in.

But the interesting part isn't the redesign. It's what happened once the tool started doing things on your behalf. Marking an order shipped fires off a background tab that talks to eBay. For a long stretch of this project's life, that automation had no way to report a failure at all:

a card whose ship tab died sat forever showing a green ✔ over the words “Marked as Shipped” while the favicon counter dropped as if the order had gone out. CHANGELOG.md — v4.21

Worse: the tab-title counter of remaining work also counted the pending overlay, so a silent failure made the batch look more finished than it was. The tool wasn't merely failing to notice. It was actively arguing that everything was fine.

Fixing that took five versions and turned into the project's spine. Nearly every feature below is downstream of it.

v4.21–4.25 three honest states

A card is pending, confirmed, or failed. Never a fourth thing wearing the face of the second.

Pending is an amber spinner that says what it's actually doing. Confirmed is green, and only arrives when eBay says so. Failed is a red banner that quotes eBay back at you and leaves the tab open, because that is the one case where a human needs to look at the page.

v4.24–4.25 how it knows

Confirmation is a positive signal, not the absence of a button.

The first version of the confirmation logic waited twelve seconds for eBay's “Mark as shipped” button. If it never appeared, it concluded the order must already be shipped and wrote a success. The changelog's own verdict on that:

which is true most of the time, and is also exactly what a slow page, a markup change or a quietly logged-out session look like. CHANGELOG.md — v4.24

Now it reads eBay's own progress stepper. And eBay renames that step rather than restyling it — an unshipped order reads “Ship by Aug 26”, and only once it ships does the same step become “Shipped Aug 23”. So the match anchors on the ship prefix and lets the icon decide state, reading two independent signals and accepting either. When neither is legible the answer is unknown — guessed in neither direction.

The failure message quotes the evidence: eBay still shows this order as NOT shipped (eBay shows “Ship by Aug 26”). You are told what the tool saw, not what it concluded.

The version after that is a post-mortem on its own tests. v4.24's suite passed only because a fixture was invented — it kept the “Shipped” label and flipped the icon, a combination eBay never renders. A hand-made fixture confirmed the assumption it was built from; the real markup did not.

v3.26–4.36 the pick-and-pack page

Everything you need to pack an order, on the card for that order.

eBay's bulk shipping page is a list of rows. Packing is a physical task — find the sticker, match it to a name, get it into the right envelope. So the page becomes a set of cards colour-coded by what they physically need, with a floating panel listing every SKU in the batch.

This is live. Type in the filter, click a SKU to jump to its card, click a batch filter to select a subset, hover an address warning.

Colour is physical, not decorative. Orange border means the sticker needs a manila envelope. Pale yellow means an LG item. A green wash means multiple items in one order, each order getting its own tint from a 40-colour palette so two adjacent multi-item orders never look like one. The amber ×2 pill means one SKU, more than one of it — the single most common packing mistake.

v4.29–4.34 filters that can't lie either

The checkbox answers “is this list filtered right now?” — not “did I click this a while ago?”

Each batch filter carries its own checkbox. It is ticked only while the selection is exactly what that filter would produce, indeterminate while the selection is a subset, and clear the moment the selection reaches outside it. Untick one order by hand in the demo above and the box drops immediately.

It reads correctly even where the sets overlap. Select 🇨🇦 Canada in the demo and the standard envelope box goes indeterminate rather than clear — a Canadian order under the threshold is still a hand-addressed envelope, just one that needs an international stamp. The box is telling you the truth: what you have selected is part of that filter's work, not all of it.

The state is derived, never remembered. […] it answers “is this list filtered right now?”, not “did I click this a while ago?”, and the second question is the one that lies. CHANGELOG.md — v4.33

Already-shipped orders are excluded from both the counts and the selection — before v4.29 a filter could quietly re-add envelopes you packed an hour ago to the print run. And a filter matching nothing stays visible but disabled, showing (0) and a tooltip: controls that vanish make the bar jump around and leave you guessing whether the feature broke or the orders ran out.

Getting these to sit flush with eBay's own “Select all” took three attempts at pixel alignment before the right answer turned out to be structural — stop reconstructing their markup and clone it, inheriting whatever their DOM really is, including the parts nobody had seen.

v4.23–4.35 a batch you can walk away from

Forty orders, one at a time, each waiting for a real outcome before the next begins.

Orders can't run in parallel: the thank-you message tab takes focus, so several at once would fight over the browser. A pre-flight dialog tells you how many orders, how many messages, and roughly how long — measured across real batches at 30s each, not guessed.

Ready
0 shipped · 8 to go

Run it. One of these eight will fail to ship, and one will ship but fail to message. Watch what the dock does at the end — the rescue sweep takes one more automated swing at the un-messaged buyer, in the background, and then reports exactly what it managed.

The sweep exists because message failures used to land as pills the seller had to notice and clear by hand, one card at a time, after the batch they had already walked away from. Its guardrails are the interesting part:

  • Exactly one attempt per card, per batch. The marker is written before the tab opens, so a throw, a reload or an eBay re-render can never turn this into a loop that keeps mailing the same buyer.
  • The draft's action is re-validated at the moment of use. An unknown action is skipped, not defaulted to the auto path — which would peek the thank-you draft and, with auto-send on, mail the buyer something the seller never chose.
  • Two failures ends it. “Two automated failures is evidence that something needs eyes, not that a third try would land.”
  • Retries open in the background, unlike the manual Retry button — that one is a deliberate click and deserves focus; this is cleanup running after you've looked away.

And it says so out loud, because “a silent recovery is indistinguishable from never having tried, and a silent failure reads as success.”

v3.26–4.36 three kinds of postage

Every order is a hand-addressed envelope, an international one, or an eBay label with tracking.

That decision drives almost everything else on the page. It comes from the order total against one configurable threshold — above $25, the margin carries a tracked label; at or under, it goes out as a plain #10 envelope, and the buyer is told why in the message: “To keep prices fair, orders at or under $25 ship without tracking.”

Because the split is derived from price rather than remembered, it stays consistent across the three places it shows up: the +tracking link on the card, the highlighted total, and whether the order is included in the Select standard envelope batch filter.

Printing them used to be the worst part of the evening. eBay gives you one print dialog per envelope; forty orders is forty dialogs. v3.34–3.43 the address as data to be linted

A stamped envelope is an expensive place to discover a bad address.

Every address is checked against structural rules before it can be printed: line count, a buyer name that isn't a number, a street line that starts with a house number (unless it's a PO Box), a valid City ST 12345 line, and a real state or territory code — all 59 of them, including the military ones.

Canada gets its own path: postal-code format and all thirteen province and territory codes. Other international destinations are skipped rather than guessed at — there are too many valid formats to lint honestly.

There is also one rule that exists purely because of an eBay quirk: a line after the name that is only digits almost always means eBay split the street number away from the street name, leaving it duplicated.

v3.79–4.28 the tab as a dashboard

You are not looking at the browser. You are at the table with a ziplock bag.

So the count of remaining work lives where you'll see it anyway: drawn onto the favicon and prefixed to the tab title. The badge went through seven iterations to stay legible at 16 pixels — a corner balloon, then full-bleed, and finally eBay's own favicon with a translucent white box across the bottom-right at 65% of the icon's width. (6) Ship — Seller Hub

Counts confirmed shipments only — a pending or failed order still counts as work to do.

The page never refreshes itself. So it watches instead.

The bulk shipping page is a snapshot from the moment it loaded. A sale that lands twenty minutes into a packing session is simply invisible. Every five minutes the script asks eBay's own awaiting-shipment endpoint what it thinks the list is, and if new order ids appear, a pill offers a reload.

Almost all of the design here is restraint. It never reloads on its own — automation tabs may be in flight and an address may be half-edited. It refuses mid-batch. It counts additions only, since an id leaving the list means shipped or cancelled and is never a reason to nag. And any response that isn't a well-formed list — a sign-in redirect, an interstitial, a shape change — is treated as inconclusive and backed off from rather than badged as news.

v4.26 was completely invisible until it had news, which made its silence ambiguous: “no new orders” and “this died an hour ago” looked exactly the same from the outside. CHANGELOG.md — v4.27

Hence the thin status line under the pill — · checked 2m ago · check now — which goes amber when a check has failed or hasn't succeeded in more than two intervals. Deliberately not a countdown: a per-second timer would turn an ambient watcher into something you watch.

v4.15–4.23 what the buyer is told

A thank-you note that reads like a person wrote it, sent exactly once.

Every shipment can carry a message. The drafts live in an external config file the script pulls at runtime, so the wording can change without touching the code — and they're filled from the order itself, not from a fixed template.

thank-you draft interactive

Note the small things. GEORGE becomes “George” — eBay hands over ALL-CAPS names, and a machine-looking greeting undoes the point of writing one. The product noun and every pronoun agree with the quantity. The tracking sentence disappears entirely above the threshold. And “tomorrow” rolls to Monday if it would land on a Sunday, because nothing ships on a Sunday.

Sending it turned out to be the hard part

For a long time the thank-you automation intermittently left the draft sitting in the box, unsent. Four separate timing bugs, all of which made a failure look identical to a success: the “Message buyer” button was clicked once before eBay had hydrated it; the composer textarea was grabbed before its iframe had bound a submit handler; the Send button was taken the first time it merely looked enabled — a server-rendered button carries no disabled attribute until JS adds one — and clicked exactly once, with the retry interval cleared immediately after; and nothing verified the outcome before the tab closed itself 1.2 seconds later.

Now every step retries, and the tab only closes on positive evidence that the message went out. If it can't confirm, it stays open with the draft intact and a red banner explaining what went wrong.

Retry can never double-send

This is the constraint that shapes the whole messaging design. The “will ship” note and the thank-you message are one-shot side effects guarded by per-order flags, so retrying a failed shipment never mails the buyer twice.

And the draft's lifecycle is split in two — peekBuyerMessage() reads it, consumeBuyerMessage() deletes it — with the delete moved to the moment the text actually lands in the box. An earlier version read and deleted as its first action, before the composer had even opened, so a failure discarded the message entirely: the order shipped, the buyer heard nothing, and there was nothing left to retry.

Everything before that point is now retryable; everything after it would double-paste, so it isn't. CHANGELOG.md — v4.23

Retry is also only offered where it can work. If a card has lost the anchor the button rebuilds from, Retry renders disabled with an explanation rather than looking clickable and doing nothing — and the Open link stays as the working escape hatch.

diagnostics

Every risky subsystem ships with a report, a dry run, and a simulator.

Not scaffolding left behind — a feature. Each of these can drive the UI into any state without contacting eBay, so a failure banner can be checked without breaking a real order, and the end-of-batch sweep can be inspected before it runs.

They pay for themselves directly. The v4.22 bug — a card that became permanently unshippable, silently, because two legitimate code paths removed its button and nothing put it back — was caught by the dry run built one version earlier.

what 112 versions taught it

      

        The rules this thing keeps rediscovering.
      

      

        None of these were decided up front. Each one is the residue of a specific evening where
        something went quietly wrong.
      

    


    

      

        
A silent failure reads as success.

        

          If an automation can fail without saying so, the interface is not neutral — it is actively
          reporting a success. Every automated path needs a failure channel, and a way to be told
          about it that survives the tab that was supposed to do the telling.
        

        v4.16 · v4.17 · v4.21 · v4.35
      

      

        
Never reason from an absence.

        

          A missing button is not evidence the work is done. It is equally consistent with a slow
          page, a markup change, and a logged-out session. Require a positive signal; when there
          isn't one, the answer is unknown, not a guess in the
          convenient direction.
        

        v4.24 · v4.16
      

      

        
Derive state; don't remember it.

        

          Remembered state answers “did I click this a while ago?” Derived state answers “is this
          true right now?” The second question is the only one worth asking, and the first one lies
          the moment anything changes underneath it.
        

        v4.33 · v3.88 · v4.36
      

      

        
Guard every side effect that reaches a buyer.

        

          Anything that messages a person is one-shot and flagged before the attempt, not after —
          so a crash, a reload or a re-render can never turn a retry into a second email to
          somebody's actual inbox.
        

        v4.21 · v4.23 · v4.35
      

      

        
Silence must be distinguishable from death.

        

          An ambient feature that only speaks when it has news is indistinguishable from one that
          died an hour ago. Show the heartbeat, not just the alarm — and make a control that has
          nothing to do render disabled rather than vanishing.
        

        v4.27 · v4.29
      

      

        
Know where automation stops and a person starts.

        

          Two automated failures is evidence that something needs eyes, not that a third try would
          land. An invalid tracking number leaves the tab open rather than submitting a bad one.
          The escape hatch is a feature, not a fallback.
        

        v4.24 · v4.35 · v3.78
      

      

        
Don't steal attention you haven't earned.

        

          Cleanup that runs after the seller has looked away opens its tabs in the background. A
          deliberate click gets focus; automated recovery doesn't. And an ambient watcher gets no
          countdown, because a per-second timer turns it into something you watch.
        

        v4.35 · v4.27 · v4.23
      

      

        
Measure. Don't infer.

        

          The batch time estimate was corrected from 20s to 30s per order across two real batches —
          the old figure under-promised a ten-order run by 40%. Three attempts at pixel alignment
          were resolved by measuring the type scale rather than eyeballing the gap.
        

        v4.23 · v4.32 · v3.94
      

      

        
Copy the platform's real markup — don't imitate it.

        

          A hand-built lookalike of eBay's checkbox rendered nothing at all, because eBay hides the
          raw input and draws the visible control from sibling icon markup. Cloning inherits
          whatever their structure really is, including the parts you haven't seen — which is the
          point, since guessing is what failed.
        

        v4.34 · v4.33
      

      

        
State what a removal costs.

        

          When the hand-reclassify pill was cut, the changelog names the one behaviour genuinely
          lost rather than describing the change as pure simplification. A feature removed without
          an accounting is a feature that comes back as a bug report.
        

        v4.36 · v4.30

Fighting a React form

          
Six versions to make three dimension fields hold their values against eBay's debounced rate-refetch. The root cause was set order, not timing — and eBay clamps a 4.125in length because the longest side must go in the length box.

        

      

      

        
4.00–4.14

        

          
Surviving re-renders

          
The US country line inferred from eBay omitting a country span; buyer notes rescued from a hidden summary element; a MutationObserver watchdog for combined-order cards that eBay re-renders after the initial pass, wiping everything injected into them.

        

      

      

        
4.15–4.20

        

          
Messaging honesty

          
A send becomes verifiable. A crash that killed the manual path is traced to a temporal dead zone — masked on the auto path by a single await that yielded long enough for the file to finish evaluating. The dispatcher stops swallowing exceptions.

        

      

      

        
4.21–4.25

        

          
Shipping honesty the core

          
Failure channels, three card states, dual failure detection, button recovery, a message-failure channel, the death of “assume shipped after 12 seconds” — and finally a post-mortem that indicts its own test fixture. v4.21 states the remaining gap out loud; v4.24 closes it three versions later.

        

      

      

        
4.26–4.28

        

          
Ambient awareness

          
A background order watch with more restraint written into it than feature. The next version gives it a face so its silence isn't ambiguous; the one after fixes its colours, because amber already means LG on this page and a notification has no business borrowing a colour that carries packing meaning.

        

      

      

        
4.29–4.36

        

          
Batch safety

          
Filters with counts and shipped-order exclusion, three rounds of alignment chasing resolved by adopting eBay's own markup, derived checkbox states, the end-of-batch message rescue sweep, and one deliberate feature removal with its cost stated plainly.

        

      

      

        
4.37–4.38

        

          
Defaults that persist

          
The last real bug in the file is a repaint quietly overwriting the seller's own choices — plus a line commented “Reset auto-send toggle to OFF at start for safety” that set it to true on every page load.

Offer Msg Picker eBay active listings

          
Ten marketing message templates in the Send Offer modal, with the discount read from the offer form itself rather than hard-coded — so a message can never promise a discount the offer doesn't send. Mounts as a sibling of eBay's React container, because mounting inside it meant the character counter re-created the textarea on every keystroke and stole focus.

        

        

          
Print Address from Gmail mail.google.com

          
A 🖨 Print address button on Etsy and eBay order emails that prints a #10 envelope from the Gmail tab itself. Parses the address out of the rendered message, because Gmail's sanitiser strips <address> entirely. No innerHTML anywhere — Gmail enforces Trusted Types, which made an earlier version throw a CSP violation and do nothing at all.
